# AIRFECTION V3 — REAL FORECAST HEATMAP + SKY PHOTO AI

This is the updated Streamlit website. Diwali Lab has been removed completely from the app. It is not an official Indian AQI or medical product.

## 1 — Run on Windows

1. Extract `AIRFECTION_V3_WEBSITE.zip` and open the **AIRFECTION_V3** folder inside VS Code.
2. In VS Code choose Terminal → New Terminal. `dir` should show `app.py` and `requirements.txt`.
3. Run:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

4. Open http://localhost:8501 .
5. Select **Forecast Heatmap**, move the 1–6 hour slider, change the city, and choose **Live · Open-Meteo models** for a data-driven (not synthetic) CAMS regional map. It needs internet. The demo map contains **fictional** values.

If PowerShell will not activate your environment, use `.\.venv\Scripts\python.exe` exactly as shown (no activation needed).

## 2 — How the heatmap works

- Live mode requests 25 coordinates in one Open-Meteo API call around the chosen city, then deduplicates *actual CAMS global model grid-cell centers*. Because CAMS global is roughly 45 km resolution, requested coordinates can resolve to the same underlying model cell.
- The region's **provider-derived US AQI** and **PM2.5 µg/m³** are alternative map display modes when US AQI is returned. **US AQI is not Indian/CPCB AQI.**
- Colors use measured **numeric forecast values**, not number of nearby stations. Green/yellow → orange → red → dark red. Inverse-distance interpolation creates an on-screen surface only within supplied regional data coverage. No data points? No heatmap. One uploaded station? One marker, no invented neighborhood heatmap.
- The selected-city **AIRFECTION ML prediction** and surrounding **CAMS regional-model forecast** are different sources. They are labeled separately; don't claim the whole map was generated by your Random Forest model.
- For a **genuine sensor-based neighborhood map**, you'll eventually need several nearby air-quality sensors with synchronized observations and a validated spatial forecasting method.

Data provider: https://open-meteo.com/en/docs/air-quality-api

## 3 — Make the Sky Photo AI work

The app uses a real **pretrained CLIP ViT-B/32** neural network; it does not require you to train from scratch. Weights download from Hugging Face on first use; allow enough space (~600 MB for CLIP model weights plus PyTorch dependencies). This feature can be resource-heavy on a free cloud host.

After the basic app is installed, stop Streamlit with Ctrl+C. Then run:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-vision.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Open **Sky Photo AI** → upload JPG/PNG under 8 MB → click **Analyze my sky**. The model ranks *visual descriptions*: clear, cloudy, possible fog, possible haze, sunrise/sunset, or no sky. **Scores are only relative within those labels; not calibrated probabilities, actual smog measurements, or AQI.** Sky AI operates independently of pollution API/forecast availability.

For a quick package/model check (requires internet on first run):

```powershell
.\.venv\Scripts\python.exe verify_sky_ai.py
```

If first download fails, verify network connectivity to huggingface.co and available memory. The app shows installation errors explicitly; it does **not** silently return pretend AI results.

## 4 — Train the Sky Photo classifier with your own images

You can adapt the pretrained CLIP image encoder using labeled-photo **class prototypes**. You are *not* retraining the complete CLIP neural network.

1. Gather photos with consent, across locations, camera devices, times of day and weather; target 100–200 examples **per class** as a start. For research-grade haze labels, also obtain synchronized visibility and PM2.5 sensor readings.
2. Create these folders (all lower case):

```text
sky_photos/
  clear/
  cloudy/
  fog/
  haze/
```

3. Put appropriate `.jpg`, `.jpeg`, `.png`, or `.webp` images in each folder. Avoid near-duplicates and heavily edited images. At least five photos per category are required by the script; 5/class is **not enough** for reliable real-world performance.
4. Run:

```powershell
.\.venv\Scripts\python.exe train_sky.py --data sky_photos --output sky_prototypes.npz
```

5. It saves `sky_prototypes.npz` and reports held-out accuracy. Restart the website; the **AIRFECTION trained prototypes** option now appears. The training script does not guarantee validity of fog-vs-haze classification.
6. Have people label new photos independently and evaluate using a test set from different days/cameras/locations. Track accuracy, F1 per class and a confusion matrix. Do not try to estimate PM2.5 or AQI from photos without synchronized reference sensors and validation.

## 5 — Add real pollution measurements

Open **Data Lab**. Upload an hourly CSV with columns `time,pm2_5` where time is the station's local time, or use the OpenAQ API download tab with your own key. Select the actual station coordinates in the sidebar first; **Automatically add matching historical weather** merges Open-Meteo weather. Then click **Use this dataset to train AIRFECTION**, select **CSV · Uploaded station data** in the sidebar.

One sensor file supports **only one map location**, not a surface. For a true multi-station heatmap you will need to process multiple stations and fit a spatial model. This release intentionally won't fabricate surrounding sensor data.

### Model architecture

- `app.py`: Streamlit website, page navigation, hourly slider, maps, image uploader.
- `heatmap.py`: gradient and localized value interpolation.
- `data_sources.py`: automated regional Open-Meteo CAMS data retrieval.
- `forecasting.py`: Random Forest trained on historical weather + PM2.5 and hour/Diwali features.
- `data_lab.py`: CSV/OpenAQ sensor importer and hourly weather matching.
- `vision_optional.py`: pretrained CLIP classifier (downloaded first run), custom prototype inference.
- `train_sky.py`: labeled-photo prototype training and simple held-out accuracy.
- `health_evidence.py`: linked WHO / research-based public health educational guidance.

Known limitations: Live regional air-quality forecasts come from CAMS, not local ground sensors; no official Indian AQI; no medical diagnosis; Sky AI has not been validated as a smog detector, and full UI and model-weight downloads require testing on the user's machine.
